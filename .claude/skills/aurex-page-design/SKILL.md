# Aurex Page Design

Use only after the relevant strategy and creative direction are sufficiently approved.

## Before building

For the page or page bundle, establish:

- page purpose
- visitor intent
- primary message
- primary conversion
- proof required
- objections to resolve
- search intent where relevant
- relationship to the site narrative
- unique media/assets needed
- creative concept moments appropriate to this page
- which of the approved 1-3 signature moments this page carries, if any

## Page narrative

Build a sequence, not a component inventory.

Each section should perform a job such as:

- orient
- promise
- demonstrate
- explain
- prove
- compare
- answer
- reduce risk
- personalize
- convert

Vary composition according to the content. Do not solve every section with heading + paragraph + three cards.

## Visual behavior

Follow the approved design system while preserving enough compositional variety to keep the experience alive.

Use imagery as content. If a needed visual is unavailable, create a clear placeholder and document the exact asset needed rather than weakening the concept.

Implement the approved signature moments with restraint. A site should normally have 1-3 total, not one novelty per section. Preserve their narrative purpose, mobile translation, reduced-motion fallback, accessibility, and performance.

## Conversion

Make CTA placement contextual. Keep the primary action recognizable across pages. Ensure forms and interactive conversion elements follow the conversion plan.

## SEO/content

Write for the visitor first while fully satisfying the page's real search intent. Use semantic structure and natural internal links. Do not pad the page to hit arbitrary word counts.

## Responsive

Design mobile structure intentionally while building. Reconsider sequence, crop, density, interaction, CTA access, and motion rather than waiting for a final stacking pass.

## Browser loop

After implementation:

1. run the page
2. inspect it visually at desktop and mobile sizes
3. compare against the approved concept and page purpose
4. review macro issues before micro details: narrative/hierarchy, composition/rhythm, imagery, type/color, signature moments, responsive translation, then fine polish
5. revise the highest-impact issues

Do not call the page finished from code inspection alone.

For a dedicated finishing cycle, use `/aurex-polish`. It permits two bounded browser-led refinement passes; it is not an invitation to redesign indefinitely.

## Bundle behavior

For internal page categories, build and approve a representative pattern first. After the pattern is sound, complete routine sibling pages autonomously while preserving unique content and intent.
