# Aurex Efficiency Rules

Apply these rules across Aurex website work.

- Use the smallest operating mode that can reliably produce an excellent result: QUICK, STANDARD, or DEEP.
- STANDARD is the normal default for meaningful production work. DEEP is not the default merely because specialist agents are available.
- Do not rerun discovery, strategy, or broad research when approved durable project artifacts already contain the answer.
- Read the smallest relevant set of files before expanding repository context.
- Before invoking a specialist agent, define the exact question and expected deliverable.
- Prefer one focused specialist over multiple overlapping specialists.
- Do not use an agent team unless parallel independent workstreams materially justify the added cost.
- Match verification depth to the risk and scope of the change.
- When a task grows materially beyond its original mode, state why the mode is escalating.
- Update `AUREX-STATUS.md` after meaningful work units so fresh sessions do not need old transcripts.
- Use `AUREX-BRIEF.md` for focused implementation handoffs. Store decisions, not chat history.
- Avoid verbose internal reports that do not change a decision or preserve useful project memory.
- Keep ChatGPT and Claude roles complementary. Do not duplicate broad external research and local implementation analysis in both systems without a reason.
